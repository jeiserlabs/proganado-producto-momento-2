1. La Realidad de la Industria 2026: ¿Por Qué React + Tailwind y No Bootstrap?

En la sustentación, el equipo debe justificar con criterio de ingeniería por qué se migró de Bootstrap 5 a React 19 + Tailwind CSS:

Criterio Técnico Bootstrap 5 (Legacy 2011–2020) React 19 + Tailwind CSS (Estándar Industria 2026)
Adopción en la Industria En declive para proyectos nuevos. Usado mayormente en mantenimiento de sistemas monolíticos heredados. Líder absoluto: React domina con ~68% de cuota en SPAs; Tailwind tiene >80% de satisfacción en el State of CSS.
Paradigma de Diseño Componentes rígidos y prehechos: Todas las webs se ven idénticas a menos que se sobreescriba con CSS pesado. Diseño atómico sin límites: Clases utilitarias directas en el elemento sin salirse del flujo de diseño.
Rendimiento y Bundle Carga hojas de estilo pesadas con cientos de clases que nunca se usan en la pantalla. Tree-shaking estricto: Vite y Tailwind purgan el CSS y solo empaquetan las clases exactas que usamos (24 kB finales).
Alineación con el Docente Tema superado en los primeros módulos de maquetación tradicional. Alineación total: En la clase del 31-Oct, el docente Felipe Piedrahita introdujo Tailwind + Flowbite en clase.

/* Barra de Progreso de Lectura con CSS Scroll-Driven */
.scroll-progress-bar {
  position: fixed;
  top: 0;
  left: 0;
  height: 4px;
  width: 100%;
  background: #198754;
  transform-origin: 0% 50%;
  z-index: 100;
  
  /* Propiedad Moderna W3C */
  animation: grow-progress auto linear;
  animation-timeline: scroll();
}

@keyframes grow-progress {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}
 1. Cero Líneas de JavaScript (0% CPU en JS):
  • Tradicionalmente se usaba window.addEventListener('scroll', ...) para calcular cuánto bajaba el usuario. Eso saturaba el procesador.
  • Con animation-timeline: scroll(), el cálculo lo realiza el motor de renderizado del navegador directamente en la tarjeta de video (GPU).
2. Cómo funciona la física del movimiento:
  • transform: scaleX(0) a scaleX(1): La barra empieza con ancho cero y se estira hasta el 100% a medida que se llega al footer.
  • transform-origin: 0% 50%: Ancla el crecimiento al borde izquierdo de la pantalla.

3. Módulo Técnico: Arquitectura de Datos (Frontend vs SQL vs NoSQL)

Para sustentar con autoridad técnica, el equipo debe dominar las diferencias entre el almacenamiento en el cliente que usamos en la web, la base de datos relacional SQL que diseñamos para la materia de BD, y la base NoSQL (MongoDB) vista en clase con el docente.

Característica 1. Almacenamiento Frontend (localStorage) 2. SQL Relacional (SQLite / PostgreSQL / SQL Server) 3. NoSQL Documental (MongoDB)
¿Dónde vive? En el navegador web de cada usuario (cliente). En un servidor o archivo de base de datos relacional local/cloud. En un servidor distribuido en formato documental.
Capacidad Máxima ~5 MB a 10 MB por dominio web. Gigabytes a Terabytes (Ilimitado según el disco). Petabytes (Escalabilidad horizontal masiva).
Estructura Pares clave-valor en texto plano (Strings/JSON). Tablas rígidas con columnas, tipos estrictos y DDL. Colecciones de documentos BSON/JSON flexibles.
Integridad Referencial Ninguna. Si borras un potrero, las vacas quedan huérfanas. Total (ACID): Llaves foráneas (FK), ON DELETE CASCADE. Por embebido o referencias manuales sin restricciones ACID rígidas.
Caso de Uso ProGanado Prototipo Web M2: Guardar el estado de la sesión y filtros sin latencia de red. Núcleo Oficial (Bases de Datos): 12 tablas con auditoría, pesaje de leche y trazabilidad sanitaria. Telemetría IoT: Lecturas por segundo de collares GPS o sensores de temperatura en campo.

4. Cómo se Conecta la Página Web a la Base de Datos en Producción

Una página web de navegador jamás se conecta directamente a una base de datos SQL por razones de ciberseguridad (se expondrían las credenciales de la base de datos a cualquier usuario que abra la consola del navegador F12). El flujo estándar de la industria es una arquitectura en tres capas:

Arquitectura Estándar Cliente-Servidor:
[Cliente: React Web] ── (HTTP GET/POST / JSON) ──► [Servidor Backend: Node.js / Express] ── (Query SQL) ──► [Base de Datos: SQLite / PostgreSQL]
Implementación en el Código Explicación del Proceso Paso a Paso 
// 1. EN EL FRONTEND (React)
// Hace una petición asíncrona a la API REST
async function cargarBovinosDesdeServidor() {
  const res = await fetch('http://localhost:3000/api/bovinos');
  const data = await res.json();
  setBovinos(data);
}

// 2. EN EL BACKEND (Node.js + Express + SQLite)
// Recibe la petición y consulta la base de datos protegida
app.get('/api/bovinos', (req, res) => {
  const query = 'SELECT * FROM bovinos WHERE estado = "En Ordeño"';
  const rows = db.prepare(query).all();
  res.json(rows); // Devuelve los datos en formato JSON
});
 1. Petición Asíncrona (Fetch API):
  • React ejecuta la función fetch() en segundo plano. La interfaz del usuario no se congela mientras viajan los datos.
2. Capa Intermedia de Seguridad (Backend REST API):
  • El servidor backend actúa como un guardia de seguridad. Valida los permisos del usuario antes de tocar la base de datos.
3. Ejecución del Query SQL:
  • El backend ejecuta la sentencia SELECT contra la base de datos relacional y convierte las filas de la tabla en un array de objetos JSON para que React los pinte en las tarjetas.

Pregunta Clave del Profesor Jonathan: "¿Por qué su página web usa React y Tailwind en lugar de Bootstrap, y cómo manejan los datos?"

Respuesta Recomendada del Expositor:
"Profesor, en ProGanado tomamos la decisión de aplicar las tecnologías que hoy dominan la industria del software. Migramos de Bootstrap a React 19 con Tailwind CSS porque nos brinda arquitectura basada en componentes modulares, mayor velocidad de renderizado y un CSS optimizado con cero desperdicio de código.

Respecto a los datos, implementamos una separación de responsabilidades: para este Momento 2, la web funciona como una SPA con persistencia en el localStorage del cliente y animaciones de scroll ejecutadas en GPU. Diseñamos este modelo en el frontend con exactamente los mismos atributos que definimos en las 12 tablas de nuestro modelo SQLite para la materia de Bases de Datos, dejando la aplicación 100% lista para conectarse mediante una API REST en el siguiente momento."
